# Security Policy

## Supported Versions

Security fixes are provided for the latest `main` branch and the most recent tagged release.

## Reporting A Vulnerability

Do not post vulnerability details or sensitive attachments in public issues.

If **Report a vulnerability** is available on the repository's
[Security advisories page](https://github.com/EnesGoker/Numtilo/security/advisories),
submit your report there privately.

If that option is unavailable, use the [bug report form](https://github.com/EnesGoker/Numtilo/issues/new?template=bug_report.yml)
only to ask the maintainer to enable GitHub private vulnerability reporting.
In required form fields, enter neutral text such as `Private reporting channel requested`
instead of vulnerability information. Do not include vulnerability details, reproduction
steps, proof-of-concept, credentials or attachments in the public form.
Wait until **Report a vulnerability** is available, then submit sensitive information
only through that private option.

In the private report, include:

- affected version/commit
- platform (macOS/Linux/Windows)
- reproduction steps
- impact assessment
- optional proof-of-concept

## Response Targets

- Initial acknowledgment: within 7 days
- Triage status update: within 14 days
- Fix timeline: depends on severity and reproducibility

## Disclosure

- Coordinated disclosure is preferred.
- A patch and release notes should be prepared before public disclosure.
